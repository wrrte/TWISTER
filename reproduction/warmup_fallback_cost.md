# 에피소드 경계 복구 비용 — 2026-11-10

3090 서버의 실제 Chopper Command 체크포인트를 CPU로 읽고 같은 파일시스템에
임시로 다시 저장했습니다. 임시 파일은 측정 뒤 제거했습니다. GPU 학습은 실행하지
않았으며 기존 체크포인트와 replay는 수정하지 않았습니다.

| 항목 | 실측 |
| --- | ---: |
| 체크포인트 크기 | 534,423,563 bytes ≈ 0.50 GiB |
| CPU 로드 | 2.92초 |
| CPU 직렬화·파일 쓰기 반환 | 1.10초 |
| 파일 `fsync`까지 포함한 기록 완료 | 5.29초 |
| 측정 프로세스 전체 최대 RSS | 990.9 MiB |

전체 RSS에는 Python·PyTorch와 읽은 체크포인트가 모두 포함되므로 학습 중 추가
메모리 비용과 같지는 않습니다. GPU에서 CPU로 복사하는 시간, replay 추가 저장,
에뮬레이터·정책의 진행 상태 저장 비용은 측정에 포함되지 않았습니다. 파일 캐시와
동시 학습의 I/O 부하에 따라 실제 비용은 달라집니다.

현재 첫 라운드의 정상 warmup 로그에는 게임당 18~140회의 에피소드 종료가 있습니다.
50,000 이전 종료만 세면 이보다 적으므로 다음은 warmup 전체 횟수에 기반한 비용
범위입니다. 각 종료마다 0.50 GiB 후보를 갱신하는 단순 방식이라면 게임·시드당:

- 추가 쓰기 총량: 약 9~70 GiB.
- 직렬화 반환 시간 누적: 약 20초~2.6분.
- 기록 완료까지 매번 기다리는 경우: 약 1.6~12.4분. 해당 게임의 실측 warmup
  시간과 비교하면 약 0.3~3.2%입니다.
- 마지막 후보 하나만 남기면 보관 공간은 약 0.50 GiB이고, 원자적 교체 중에는
  약 1 GiB가 필요합니다. 9~70 GiB는 누적 쓰기량이며 보관 공간이 아닙니다.
- RAM에 후보를 보관하면 직렬화 쓰기를 줄일 수 있지만, 변경되지 않는 파라미터·
  optimizer 사본만 약 0.50 GiB/worker, 교체 중에는 두 사본이 필요합니다.
  replay 메타데이터와 진행 중인 환경·정책 상태는 별도입니다.

또한 학습 환경이 4개이므로 마지막으로 **한 에피소드**가 끝난 시점은 모든 환경의
안전한 재시작 경계가 아닙니다. 나머지 환경의 에피소드를 끊지 않으려면 에뮬레이터
상태·정책 캐시·수집 스트림도 저장·복원해야 합니다. 기존 체크포인트에는 이 상태가
없으므로 과거 파일만으로 완전한 연속성을 복원할 수 없습니다.

개별 저장 비용은 감당할 수 있는 수준이지만, 드문 예외를 위해 정상 게임과 모든
시드에도 반복 저장·상태 복제 비용을 더하게 됩니다. 이번에는 rolling snapshot을
추가하지 않고, shared warmup을 사용할 수 없는 시드만 독립 학습하는 쪽을 선택했습니다.

정상 시드는 기존처럼 에피소드가 끝난 shared warmup에서 ON/OFF를 시작합니다.
예외 시드는 ON을 원래 시드로 처음부터 학습합니다. 점수 기준을 통과하면,
환경을 일시 정지하거나 수집을 재개하지 않고 전체 예산을 채운 warmup을 OFF로
재사용합니다. 이미 retrieval OFF로 학습한 가중치이므로 최종 평가만 필요합니다.
체크포인트는 hard link하여 추가 대용량 복사를 피합니다. 이번 Chopper Command
시드 3090은 이 조건에 해당하므로 추가 학습은 ON 1회이며 OFF는 평가만 수행합니다.

warmup이 미완료이거나 환경 일시 정지·수집 재개 이력 때문에 baseline으로 쓸 수
없으면 OFF도 같은 시드·전체 예산으로 학습합니다. 이는 모든 경우에 더 빠른
방식이라는 주장이 아니라, 정상 실행에 반복 저장 비용을 추가하지 않으면서
검증 가능한 기존 baseline 학습 결과를 재사용하는 선택입니다.
